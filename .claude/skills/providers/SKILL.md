# Провайдеры: кто свободен и кому что отдать

Провайдер не закреплён навсегда — он выбирается **на момент запуска волны** по остаткам
окон. Инструмент один:

```
orca account list --json
```

Читать в нём: `rateLimits.<провайдер>.weekly.usedPercent` (+ `session` у Claude,
+ отдельное окно `fableWeekly` — у Fable свой недельный бюджет), `resetsAt`/`resetDescription`,
`status` (`ok`/`unavailable`), и **`inactiveClaudeAccounts[].rateLimits`** — лимиты
неактивных аккаунтов Claude видны без переключения.

**Правило резерва: окно, где осталось меньше 15 %, в волну не берётся вовсе** — остаток
нужен на доведение уже начатого («Студия Игор», подтверждено там смертью пачки на 232k
токенов). Использовано ≥ 85 % → провайдер для новой работы недоступен, смотри следующий
в цепочке.

## Цепочки «роль → провайдер», в порядке падения

| Роль | 1-й выбор | 2-й | 3-й | Дальше |
|---|---|---|---|---|
| **Тесты, приёмка, плейтесты, массовые прогоны** | codex `gpt-5.6-luna`, effort `high` | Claude дешёвый: `claude-haiku-4-5`, затем `claude-sonnet-5` (активный аккаунт) | второй аккаунт Claude (переключить в Orca) | ждать сброса окна, работу не ослаблять |
| **Код бригад (путь детерминизма, Core/CartKit)** | Claude opus-уровня — Agent tool в сессии или Orca-воркер `claude` | второй аккаунт Claude | codex `gpt-5.6-sol` effort `high` — **только с обязательным глубоким ревью** (PLAYBOOK §8: путь симуляции чужому провайдеру без ревью не отдаётся) | ждать |
| **Адверсариальное ревью** | Claude opus-уровня | codex `gpt-5.6-sol` как второй взгляд | — | ревью не пропускается ради лимитов |
| **Разведка (веб, первоисточники)** | что дешевле из живого: `gpt-5.6-luna` / `claude-sonnet-5`, effort `medium` | любой живой | — | — |
| **Архитектура, спеки, оркестрация** | Fable (сессия) — у него **своё** окно `fableWeekly`, общее не жжёт | `claude-opus-5` | — | — |

Уровень ризонинга: у codex — `-c model_reasoning_effort="low|medium|high|xhigh"`;
`high` для тестов и кода, `medium/low` для механических прогонов. У Claude-агентов —
параметр `effort` вызова Agent tool: `low` для механики, выше — для verify/judge.

Три правила экономии (перенесены из «Студии Игор», там добыты замером):
- **Экономия берётся из меньшего числа стартов, а не из ослабления модели** — каждый
  старт заново платит за чтение правил и разбор кода.
- **Незаменимый провайдер тратится последним**: сначала отдай ему то, чего никто другой
  не сделает.
- **Координатор — постоянный расход**: круг без работы стоит токенов, пустой круг пропускается.

## Как поднять воркера

**Claude в этой сессии** (жжёт активный аккаунт Claude, роли уже описаны):
Agent tool, `subagent_type`: `brigade` / `scout` / `acceptor` / `adversary`.

**Codex через Orca** (модель и effort принимает только команда терминала,
`worktree create --agent codex` флагов модели не берёт):

```
orca terminal create --worktree active --title "<роль>" \
  --command 'codex --model gpt-5.6-luna -c model_reasoning_effort="high"' --json
orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 60000 --json
orca terminal send --terminal <handle> --text "<спека целиком>" --enter --json
```

Для изолированной работы — сначала `orca worktree create --name <задача> --no-parent --json`
и `--worktree id:<repoId>::<путь>` вместо `active`.

**Claude-воркер отдельным терминалом** (когда сессию-оркестратора нельзя занимать):
та же схема с `--command 'claude --model claude-sonnet-5'`.

**Спека для не-Claude воркера**: он не видит `.claude/agents/` автоматически — вставь
текст роли из `.claude/agents/<роль>.md` в начало спеки, затем задачу. В спеке — глагол,
ветка/зона и прямое «работа не сделана, если своих правок нет»: воркеры codex пересказывали
план и сдавали пустое дерево («Студия Игор», 3 случая из 4).

## Переключение аккаунтов Claude

CLI умеет только `orca account list` и `orca account add`; **активный аккаунт
переключается в приложении Orca** (Accounts). Порядок: увидел исчерпание активного →
проверь `inactiveClaudeAccounts` в JSON → если запасной жив, попроси владельца
переключить (или согласуй переключение) → волну поднимай только после переключения.
Не переключать под живыми воркерами: новые логины получат другой аккаунт, старые — нет,
и расход перестанет читаться.

## Известные отказы запуска (перенесено из «Студии Игор», числа их)

1. **Спека не доставлена** — примерно каждый третий запуск терминального воркера.
   Признак: подсказка по умолчанию или `[Pasted text …]` в поле ввода при нуле следов
   работы. Лечится `orca terminal send --enter --text ""`; успех — появившийся спиннер,
   а не факт отправки байтов.
2. **`400 … not supported when using Codex with a ChatGPT account`** — слетевшая
   подписка, а не снятая модель: смотреть `codex debug models`, говорить владельцу.
   `Selected model is at capacity` — взять соседнюю модель той же цепочки.
3. **Баннер в хвосте терминала** стоит и у не начавшего, и у закончившего воркера —
   различают следы работы выше баннера; лечения противоположны (одному Enter, у другого
   забрать работу).

## Пример разбора реального снимка (2026-08-18, эта машина)

- codex: weekly **100 %** → luna недоступна до `Wed 22:07`; тестовые роли падают
  на 2-й выбор (haiku/sonnet активного аккаунта Claude).
- Claude запасной (неактивный): weekly **100 %** → запасного аккаунта сегодня нет,
  сброс `Sat 7:59`.
- Claude активный: session 37 %, weekly 18 %, fable 11 % → вся волна дня едет на нём;
  Fable-оркестрация — из своего окна.

Вывод из снимка и есть форма ответа: «кто недоступен и до когда, кто держит волну,
какая роль на какой модели».
