# digger

Копатель в духе Boulder Dash — демо-картридж вехи M4, этап 3. Пещера 40×24 клетки
(2.5 экрана в ширину, 3 в высоту), камера следует за игроком. Копаешь землю, собираешь
самоцветы, будишь валуны — и не стоишь под ними. Выход открывается, когда в пещере
осталось два несобранных самоцвета.

Запуск: `quarp run carts/digger` (спайк разрешения — `quarp run carts/digger --profile 8w`).

## Управление

Стрелки. Шаг мира — раз в 6 тиков (10 шагов в секунду); направление, нажатое между шагами,
запоминается и применяется на ближайшем шаге. Дальше — правила, ради которых рука попадает
туда, куда целилась:

| Что делает рука | Что делает копатель |
|---|---|
| нажатие любой длины **до 18 тиков** (0.3 с) | ровно **одна** клетка |
| удержание | первая клетка сразу, вторая — через **18 тиков** (ровно, в какой бы тик цикла ни пришлось нажатие), дальше по клетке каждые 6 тиков |
| отпускание в середине бега | бег кончается на ближайшем шаге, лишней клетки нет |

Плейтест 2026-08-18 («управление слишком чувствительное») нашёл именно это: защёлка
читала кнопку уровнем (`Btn`), то есть **всё ещё зажатая** кнопка перевзводила её каждый тик
и перекупала следующий шаг. Тап в 100 мс давал две клетки в пяти фазах шестицикла из шести,
тап в 133 мс — три, причём третья приходила через 83 мс после того, как кнопку отпустили.
Стало: нажатие читается фронтом (`Btnp`) и закрывает за собой ворота повтора на 18 тиков.
Время до **первой** клетки не изменилось (0–5 тиков до ближайшего шага мира) — это часы мира,
а их этот фикс не трогает: валун по-прежнему падает на клетку за шаг.

## Правила

| Что | Как |
|---|---|
| земля | копается проходом сквозь неё, клетка остаётся пустой (`Mset`) |
| самоцвет | подбирается проходом; собрал сколько нужно — выход открылся |
| валун | лишившись опоры, **не двигается в тот же шаг**: он «срывается» и падает на следующем. Эта одна ступенька и есть разница между «выкопал под валуном и пошёл дальше» и «выкопал под валуном и умер» |
| валун в полёте | входит в клетку игрока — игрок раздавлен |
| валун на круглом | скатывается вбок: сначала влево, потом вправо; в клетку игрока не скатывается никогда |
| толчок | лежащий валун можно толкнуть вбок, если за ним пусто; валун в полёте — нельзя |
| порядок обновления | ряды снизу вверх, в ряду слева направо. Снизу вверх — чтобы ничто не упало дважды за шаг; клетка, в которую валун **скатился вправо**, пропускается, потому что это единственная дырка такого обхода |

## Файлы

| Файл | Что это |
|---|---|
| `map.csv` | авторская карта ([MAP-FORMAT.md](../../docs/MAP-FORMAT.md)); 72 строки по 256 значений, пещера — левый верхний угол 40×24 |
| `map.bin` | собранная карта; **генерируется, но лежит в репозитории** — иначе `.quarp8` не собрать без тулинга |
| `sfx.txt`, `music.txt` | авторский звук ([AUDIO-FORMAT.md](../../docs/AUDIO-FORMAT.md) §6) |
| `sfx.bin`, `music.bin` | собранные банки, там же и по той же причине |
| `replays/walkthrough.input` | скриптованное прохождение до победы (M4 Р20) |

Спрайтов-файлов нет: лист рисуется кодом через `Sset` в `Init` (M4 Р16), свойства тайлов —
флаги спрайтов (`Fset`/`Fget`), а не список `if`-ов.

Уровень нигде не описан дважды: `Init` один раз проходит карту и вычисляет из неё границы
пещеры, число самоцветов, стартовую клетку (тайл-маркер 7, который тут же стирается) и
клетку выхода. Единственное число про самоцветы, которое живёт в коде, — сколько их
разрешено не собрать (`GemsSpare = 2`).

## Пересборка

```
quarp map build carts/digger            # map.csv -> map.bin
quarp audio build carts/digger          # sfx.txt/music.txt -> sfx.bin/music.bin
quarp build carts/digger                # компиляция и все проверки, без окна и без тиков
```

Проверка «сходится ли собранное с текстом» — то же самое с `--check` (это и делает CI).

## Прохождение

`replays/walkthrough.input` — трек ввода, а не запись: `.qrpr` из него получается за
секунду и в репозитории не лежит.

```
quarp replay record carts/digger -o carts/digger/replays/walkthrough.qrpr \
    --ticks 996 --input-file carts/digger/replays/walkthrough.input
```

996 тиков (16.6 с), 166 шагов мира, 128 из них с движением; 5 из 7 самоцветов, два валуна
уронены, один толкнут; на 924-м тике открывается выход, на 996-м игрок в него входит.
Хэш кадра прохождения — `2282d532c863e044`, у холостого сима той же длины —
`6afa17f46813c3b0`: сценарий действительно играет, а не смотрит в статичный экран (M4 Р20).

Что в нём видно приборно (значения читаются `Mget`-зондом, тики — контрольными точками
`--every 1`): на тике 6 первая же клетка копается — `Mget(1,2)` 1 → 0; на 66-м копатель
выкапывает (9,2), и валун над ним теряет опору — `Mget(9,1)` 3 → 8; на 72-м валун падает
в (9,2), когда копатель уже в (10,2) — та самая одна ступенька форы; на 78-м он
приземляется — `Mget(9,2)` 8 → 3; на 102-м его толкают на запад. Второй валун: 264 / 270 /
276. Выход `Mget(38,22)` 5 → 6 на тике 924.

Трек — заодно негативный контроль правки управления: он рассчитан на то, что нажатие стоит
ровно одну клетку. Прогони его на защёлке до фикса — каждое удержание проскакивает,
копатель промахивается мимо первого самоцвета, застревает на 2 из 5 и выхода не открывает
вовсе. Раньше трек занимал 768 тиков: клетки те же, маршрут тот же, разница — 38 шагов,
которые копатель теперь стоит в воротах повтора.
