# Стиль кода и правила разработки

## Языки

| Что | Язык |
|---|---|
| Документация проекта (`docs/`, README) | русский |
| Код: идентификаторы, комментарии, XML-doc публичного API | английский |
| Сообщения коммитов | английский, короткий императив («Add fixed-point Sin table») |

Публичный API (`Quarp.Api`) документируется XML-doc обязательно — это то, что увидит
автор картриджа в подсказках IDE. Остальной код — комментарии только там, где неочевидно «почему».

## Базовое

- **.NET 10 (LTS), C# последней версии.** Обновление на новые LTS — отдельным решением.
- `<Nullable>enable</Nullable>` везде, предупреждения = ошибки в `Core` и `Api`.
- Файловые namespace (`namespace Quarp.Core;`), один публичный тип — один файл.
- Отступ 4 пробела; `var` — когда тип очевиден справа; фигурные скобки всегда.
- Именование — стандарт Microsoft: `PascalCase` для типов/методов/свойств,
  `camelCase` для локальных и параметров, `_camelCase` для приватных полей.
- `.editorconfig` в корне — источник истины для форматирования (появляется в M0);
  этот документ — источник истины для правил, которые `.editorconfig` не выражает.

## Правила ядра (Quarp.Core) — строгие

Ядро — горячий путь, исполняется 60 раз в секунду на Raspberry Pi.

1. **Ноль аллокаций на тик.** Все буферы — заранее; `Span<T>`/массивы, никаких
   `new` в `Tick`-пути. Проверяется бенчмарком с `GC.GetAllocatedBytesForCurrentThread`.
2. **Никакого LINQ, лямбд и `foreach` по интерфейсам** в тик-пути (скрытые аллокации).
   В холодном коде (загрузка картриджа) — можно.
3. **Никакого float в симуляции** — только `int`/`Fix`. float допустим в коде, который
   готовит данные для оболочки (и то по необходимости).
4. **Никакого доступа к среде**: ни `DateTime`, ни `Environment`, ни файлов, ни потоков.
   Ядро — детерминированная функция. Всё внешнее приходит параметрами.
5. **`struct`-first** для горячих данных (состояние канала звука, спрайт-курсор и т.п.),
   осознанные `readonly`/`in` где уместно.
6. **`[SkipLocalsInit]` запрещён; `stackalloc` — только с немедленной полной
   инициализацией.** Чтение недозаполненного стекового буфера — источник недетерминизма,
   который golden-master ловит плохо: мусор в стеке часто совпадает между прогонами
   на одной машине и расходится между машинами.

## Правила API (Quarp.Api)

- Поверхность минимальна и стабильна: каждый новый публичный метод — через ADR.
- Сигнатуры дружелюбны к новичку: значения по умолчанию вместо перегрузок-простыней,
  `enum` вместо магических int (`Button.Right`, не `1`).
- Ничего из `System.*` в сигнатурах публичного API, кроме примитивов — API должен
  переживать смену BCL безболезненно.

## Тесты

- `Core` покрывается golden-master-тестами: реплей → последовательность хэшей кадров.
  Любое изменение растеризатора, сломавшее хэш, — осознанное решение с обновлением эталона.
- Детерминизм-тест на двух архитектурах (x64/ARM64) — обязательная часть CI с вехи M2.
- Юнит-тесты на `Fix` и `SMath` — сравнение с эталонными таблицами, граничные значения.

## Git

- Ветка `main` всегда собирается. Фичи — в ветках, вливание — когда собирается и тесты зелёные.
- Коммиты маленькие и тематические. В теле коммита — «почему», если неочевидно.
- Теги на вехи дорожной карты (`m1`, `m2`, ...).

## Чужой код

- Куски из Pixel Vision 8 — можно (лицензия MS-PL): файл сохраняет шапку MS-PL,
  факт заимствования отмечается в комментарии шапки. Списком таких файлов владеет
  `docs/THIRD-PARTY.md` (создать при первом заимствовании).
- Из TIC-80/PICO-8 код не берём (Си / закрытый) — только идеи и форматы данных.
