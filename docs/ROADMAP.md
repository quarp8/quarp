# Дорожная карта

Без дат — это хобби, и главный риск проекта не техника, а выгорание (все мёртвые
фэнтези-консоли умерли именно от него). Правила движения:

- Веха закрыта, когда выполнен её «критерий готово», а не когда «почти работает».
- Порядок принят решением ADR-004: **профиль 8 до рабочего состояния на Windows →
  остальные платформы → профиль 16 → публичный запуск сразу с обоими профилями.**
- Ратификация SPEC-8 — двухэтапная (ADR-012): заморозка в M0, финальная ратификация
  в конце M4, когда есть демо-игры для проверки самого рискованного решения (128×72).
- До публичного запуска проект не анонсируется — тихий репозиторий.
- Вехи M0–M7 последовательны; M8–M10 могут идти параллельно, их номера — не порядок.

## M0 — Фундамент
SPEC-8 **заморожена**: закрыты все 🔶, кроме разрешения экрана (модель палитры
зафиксирована — ADR-016, hex-черновик валидируется до M4; звук — моно; подсчёт кода —
без комментариев); дальше изменения только через ADR. Выбрано
публичное имя (ADR-008). Финализирована лицензия (ADR-011: MIT + MS-PL для заимствований).
`git init`, скелет решения по ARCHITECTURE (включая заготовки Shell.Desktop и Cli —
см. таблицу оболочек), `.editorconfig`.
**Готово:** `quarp run` показывает окно 128×72 с тестовым паттерном палитры, целочисленный масштаб.

## M1 — Ядро профиля 8 + картриджи (Windows)
Framebuffer, растеризатор (весь графический API), ввод, фиксированные тики; формат `.quarp8`;
Roslyn-конвейер (компиляция + проверка метаданных по allowlist + embedded PDB) + ALC;
hot reload в режиме «перезапуск»; черновик `API-8.md` с разделом «рассмотрено и решено»;
первый картридж-игра.
**Готово:** «змейка» лежит в `carts/`, правка её кода в VS Code подхватывается на лету,
исключение в коде картриджа показывает номер строки.

## M2 — Детерминизм ✅ ВЫПОЛНЕНА (2026-08-18)
`Fix`, `SMath`, RNG (xoshiro + splitmix64), лог ввода, снимок постоянной памяти в реплее;
перемотка вперёд/назад, замедление/ускорение; hot reload «продолжение» (ресимуляция);
замер headless-скорости ресимуляции (число — в ARCHITECTURE §4); golden-master-тесты
(framebuffer + PCM); CI-тест детерминизма x64 vs arm64 на бесплатных arm64-раннерах
GitHub (репозиторий публичный — ADR-015); анализатор v1 (бан float/Random/DateTime/Task,
предупреждение на foreach по словарю).
**Готово:** реплей «змейки», записанный на Windows-x64, даёт идентичные хэши кадров
на linux-arm64 (CI или headless-прогон); правка кода посреди игры возвращает
в то же место игры.

**Доказано** (CI run 32083958003, коммит cb9439d, все 5 джобов зелёные):
- эталонный реплей — 3000 тиков живой игры, 150 контрольных точек, все различны;
- `golden_final` = `24a6eb974ff922e4` и `sim_final` = `37c481f3e17fab02` — **совпадают
  на windows-x64 и linux-arm64**, точка за точкой;
- реплей, записанный на x64, воспроизведён на arm64: 150 из 150 совпали;
- `.qrpr`, перезаписанный из своего же сценария нажатий, побайтово одинаков
  на обеих архитектурах (`regen_sha256`);
- продолжение после правки кода доказано вживую: `reload OK — continuing at tick 582`.

Осталось хвостом (не блокирует веху, разобрать в M3): декодер реплеев не проверяет
2 из 7 краевых случаев формата (REPLAY-FORMAT §4).

## M3 — Звук
APU: 4 канала, моно, целочисленный синтез; форматы `sfx.bin`/`music.bin`; мини-трекер
данных (текстовый формат + CLI-конвертер, UI позже); звук в демо-игре; замер фактической
аудио-латентности оболочки — часть критерия готовности. Здесь же — **перф-спайк веб-ядра**
(ядро+APU в wasm: интерпретатор vs AOT, замер тика), чтобы сюрпризы не всплыли в M7.
**Готово:** «змейка» пищит и играет фоновую тему; PCM-хэши входят в golden-master;
известны цифры латентности и веб-производительности.

## M4 — Инструменты, контент, финальная ратификация
Финализация формата картриджа; CLI полный (`new/run/build/pack/replay`); workflow внешних
редакторов (Aseprite для PNG-листа; решение по карте: свой мини-редактор против импорта
из Tiled); **демо-игры, включая обязательные «худшие случаи» для проверки 128×72:
платформер с вертикальным движением и диалоговая сцена** + безопасные жанры (змейка,
брейкаут-лайк, копатель, мини-рогалик, шмап). По итогам — решение 128×72 vs 160×90,
финальные hex-значения палитры (ADR-016) и **финальная ратификация SPEC-8 вместе
с API-8.md** (ADR-012). С этого момента спека перманентна.
**Готово:** человек с нашим README делает игру, не задавая нам вопросов; SPEC-8
ратифицирована на основании сыгранных прототипов.

## M5 — Платформы профиля 8
Linux, macOS, Raspberry Pi/uConsole (linux-arm64, публикация self-contained);
спайк DesktopGL vs DesktopVK на реальном uConsole (есть ли arm64-нативки VK — см. риски);
упаковка релизов; черновая страница на itch.io (скрытая).
**Готово:** все демо идут на uConsole 60 FPS.

## M6 — Профиль 16
Закрыть 🔶 SPEC-16 (палитра А/Б, Sspr, слои карты, PCM-сэмплы, режим запуска `.quarp8`)
с учётом опыта M1–M4, ратифицировать; `Profile16` в ядре (данные, не форк кода!);
вращение 90°/Sspr, wavetable, 8 каналов, стерео; портировать 1–2 демо + один
«показательный» картридж уровня 16.
**Готово:** оба профиля живут в одной сборке, `quarp new -p 16` работает.

## M7 — Публичный запуск
Веб-плеер (wasmbrowser-оболочка; отдельное время на AudioWorklet — самая капризная часть)
и экспорт картриджа в HTML-страницу (~10–20 МБ — принимаем для v1) — урок PICO-8:
«кликнул ссылку — играешь» решает всё; документация API на английском; сайт-одностраничник;
релиз на itch.io (бесплатно) + GitHub; посты: Show HN, r/csharp, r/fantasyconsoles,
форум Lexaloffle (вежливо, без слова PICO в имени).
**Готово:** незнакомец может: поиграть в браузере → скачать → сделать игру → поделиться файлом.

## M8 — Android
MonoGame Android-таргет, экранные кнопки, open/share картриджей, Google Play (политика
допускает интерпретируемый/VM-код; остаётся риск трактовки — не блокер для хобби).
Hot reload на Android — только «перезапуск»: Mono не выгружает collectible ALC,
режим «продолжение» там будет течь сборками.
**Готово:** картридж, присланный в мессенджер, открывается на телефоне в два тапа.

## M9 — Встроенные редакторы
Спрайты, карта, трекер — в оболочке (хостовый UI). Цель — самодостаточность консоли
на устройствах без VS Code (uConsole в кресле).

## M10 — Сообщество
Джем вскоре после M7, пока держится волна интереса (урок WASM-4: джем сразу = библиотека
игр; призы символические — деньги не помогают, помогает свежесть момента); шаблоны-заготовки;
3–5 письменных туториалов по жанрам; витрина картриджей на сайте.

## Осознанно отложено (не делать раньше времени)

- iOS (решение после M8; веб уже закрывает «поиграть на айфоне»).
- WASM-песочница для чужих картриджей (когда появится реальный обмен).
- Онлайн-каталог внутри консоли (аналог SPLORE) — сначала файлы и веб-витрина.
- Снапшоты состояния через source-generator (путь описан в ARCHITECTURE §4) — пока
  хватает ресимуляции на коротких сессиях.
- Консоли (Switch/PS/Xbox) — закрыто исследованием: UGC-код там не пропустят.

## Главные риски

| Риск | Смягчение |
|---|---|
| Выгорание соло-разработчика | маленькие вехи, никаких обещаний публике до M7, паузы — норма |
| 128×72 окажется слишком тесным | двухэтапная ратификация: решение после прототипов «худших жанров» в M4; запасной вариант 160×90 готов |
| Детерминизм сломается на краях | CI-тест на двух архитектурах с M2, не позже; правила SPEC-8 §7 закрывают известные источники (словари, культура, float) |
| DesktopVK — платформа первого выпуска, arm64-нативки не подтверждены | старт на DesktopGL; VK — только после спайка на uConsole в M5 |
| Веб-оболочка окажется медленной/капризной (AOT, AudioWorklet) | перф-спайк уже в M3, а не сюрприз в M7 |
| Соблазн раздуть спеки | перманентность после ратификации, изменения только через ADR |
| MonoGame Android окажется капризным (.NET 10 churn) | ядро чистое — в худшем случае оболочку Android пишем на SDL3/Silk без потери ядра |
