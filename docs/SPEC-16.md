# Спецификация: Профиль 16

**Статус: ЧЕРНОВИК.** Правила те же, что у [SPEC-8](SPEC-8.md): после ратификации —
перманентно. Открытые вопросы — 🔶. Ратифицируется **позже** SPEC-8 (веха M6),
с учётом опыта первых игр профиля 8.

Философия профиля: «та самая PICO-16, которую сообщество просит с 2017 года» —
следующее поколение той же идеи, а не безлимитный движок. Ориентир по ощущениям —
NES → SNES: больше, красивее, но всё ещё тесно.

## 0. Отношение к профилю 8

Строгое правило **×2**: экран ровно вдвое больше по каждой стороне, базовый тайл вдвое
больше, логическая сетка экрана **та же — 16×9 тайлов**. Игра профиля 8 концептуально
переносится на профиль 16 «клетка в клетку». Один редактор, один формат картриджа,
один API (+ несколько новых вызовов). Обратно: консоль профиля 16 умеет запускать
картриджи профиля 8 (в масштабе ×2 — 🔶 или с полями 1:1 по центру? решить в M6).

## 1. Экран

| Параметр | Значение |
|---|---|
| Разрешение | **256×144**, 16:9 |
| Сетка тайлов | **16×9** тайлов по 16×16 |
| Частота | 60 FPS / 60 тиков |
| Буфер | индексированный, 1 байт/пиксель (0–31) |

Масштабирование: ×5 = 720p (uConsole — пиксель-в-пиксель), ×10 = 1440p, ×15 = 4K.
На 1080p точный масштаб ×7.5 — по умолчанию оболочка использует целочисленный ×7
с тонкими полями; сглаженный нецелый режим — опциональная настройка оболочки
(ARCHITECTURE §5).

## 2. Цвет

- **32 цвета одновременно.**
- 🔶 Два варианта: (А) фиксированная кураторская палитра на 32 цвета — сильная визуальная
  идентичность, проще; (Б) 32 слота, выбираемые картриджем из мастер-палитры 512 (RGB333 —
  как у Sega Mega Drive; у SNES была RGB555/32768) — гибче, но игры выглядят разношёрстно
  и «мастер-512» даёт скорее Genesis-вид. Предварительный выбор — **А**, и после ADR-016
  у варианта А появился естественный кандидат: **видимая палитра профиля 16 = полный
  мастер-набор 32 профиля 8** (видимые 16 + секретные 16 становятся все видимыми) —
  идеальная связность семейства ×2 и знакомые цвета при апгрейде. Решить в M6.
- `Pal`/`Palt` — как в профиле 8.

## 3. Графические данные

| Ресурс | Лимит | Память |
|---|---|---|
| Лист спрайтов | 256×256 px = **256 спрайтов 16×16** | 64 КБ (8 бит/пиксель) |
| Карта | **256×72 тайлов** = 16×8 экранов = 128 экранов | 18 КБ |
| Флаги спрайтов | 8 флагов на спрайт | 256 байт |

Карта в тайлах такая же, как у профиля 8, но тайлы вдвое больше — мир физически
в 4 раза просторнее.

Новое по сравнению с профилем 8:
- **Вращение и отражение спрайтов**: `Spr` получает угол с шагом 90° + флипы (решено
  предварительно). Историческая справка, чтобы не спорить о «SNES feel»: SNES аппаратно
  спрайты **не** вращала вовсе (OAM — только флипы; повороты рисовали кадрами анимации,
  а Mode 7 вращал фоновый слой) — так что шаг 90° уже щедрее оригинала. Аффинное вращение
  фона («Mode 7» для `Map`) — осознанно **не в v1**.
- **`Sspr`** — растяжение произвольного прямоугольника листа в прямоугольник экрана
  (наезды камеры, большие боссы, эффекты) — предварительно **да**, 🔶 подтвердить в M6.
  Это ответ на предсказуемую жалобу №1 мигрантов с PICO-8; в профиле 8 его нет осознанно
  (SPEC-8 §3).
- Два вызова карты с приоритетами (`Map(..., layer: 0/1)`) — 🔶 подтвердить в M6, когда
  станет ясно, нужен ли настоящий второй слой в данных карты.

## 4. Звук

| Параметр | Значение |
|---|---|
| Выход | **стерео, панорама на канал** (решено, ADR-013 — стереопанорама была базовой частью звучания 16-битной эпохи; формат `sfx.bin` профиля 16 сразу проектируется со стерео-полем) |
| Каналы | **8** |
| Волны | как профиль 8 + wavetable (16 пользовательских волн по 32 сэмпла) |
| SFX | 128 слотов × 64 шага |
| Музыка | 128 паттернов × 8 каналов |

🔶 PCM-сэмплы (короткие, для голоса/ударных): вариант «до 16 сэмплов по 4 КБ» —
решить в M6; риск раздуть картриджи и потерять чиптюн-идентичность.

## 5. Ввод

- До **4 игроков**.
- На игрока: D-pad, **A/B/X/Y**, **L/R**, **Start/Select** — уровень SNES-пада.
- Те же правила: только логические кнопки, маппинг в оболочке.

## 6. Картридж

- Файл `*.quarp16`, контейнер тот же, что у `*.quarp8`.
- Лимиты: **исходный код ≤ 256 КБ**, **картридж ≤ 512 КБ**.
- Сохранения: 256 ячеек по 4 байта.

## 7. Время и детерминизм

Идентично профилю 8 (см. [SPEC-8 §7](SPEC-8.md#7-модель-времени-и-детерминизм)):
60 тиков, только `int`/`Fix` во всём коде картриджа (float запрещён целиком), консольные
`SMath`/RNG, входы симуляции — кнопки + снимок постоянной памяти, реплеи/перемотка
из коробки. Ориентир производительности: `Update` ≤ 4 мс на Raspberry Pi CM4.

## 8. API

Полный API профиля 8 + добавки: параметры вращения/масштаба в `Spr`, слой в `Map`,
wavetable-функции, кнопки A/B/X/Y/L/R/Select, 4 игрока. Отдельный документ `API-16.md` в M6.
