# M9 — рабочий приказ (внутренний документ оркестрации)

Критерий вехи (ADR-026, порция 1 «арт»): quarp.exe без аргументов показывает библиотеку
игр; спрайты, карта и флаги нового картриджа делаются целиком внутри Quarp — без
Aseprite, Tiled и ручного CSV; round-trip арта существующих демо байт-в-байт;
финальная приёмка — владелец сам рисует мини-уровень и говорит «удобно».

Смысл вехи. M4 доказал, что на консоли можно СДЕЛАТЬ игру; M9 делает так, чтобы её
было ПРИЯТНО делать — и чтобы консоль встречала человека лицом (библиотекой игр), а не тестовой
радугой. Четыре независимых костыля бригад M4 (парсеры hex-строк, генераторы карт)
— это спецификация инструмента, который здесь строится.

Решение владельца о курсе (ADR-025): только Windows до финальных этапов; кросс-арх
CI остаётся как доказательство детерминизма. Лесенка редакторов (ADR-026): сейчас
арт, затем звук, потом код — эта веха несёт только порцию «арт».

## Уроки прошлых вех (обязательно каждой бригаде; полные тексты — M4-WORKORDER §1)

1. Приказ — не истина: числа и имена сверять с первоисточником, расхождение — в отчёт.
2. Зелёный тест ничего не стоит, пока не показано красное (негативный контроль
   с возвратом по sha256).
3. Отчёт без личного прогона недействителен.
4. Параллельные бригады не запускают dotnet (дерутся за obj/); компилирует организатор.
5. Убивать только свои процессы и только по PID; чужой процесс — строка в отчёте.
6. Якоря не двигать молча.
7. НОВОЕ ДЛЯ M9 — ни один видимый пиксель UI не едет в релиз мимо глаза владельца
   (урок шрифтов M4, куплен дважды): вёрстка, иконки, цвета библиотеки и редакторов
   показываются владельцу скриншотом/батником ДО приёмки этапа.

## Якоря вехи (не должны измениться ни на одном этапе M9)

Все 8 значений scripts/check-anchors.sh (таблица — PLAYBOOK §4) и все 12 хэшей
carts/demo-goldens.tsv. Редакторы живут в оболочке и не имеют права трогать путь
симуляции: внутренности Quarp.Core и библиотека Quarp.Api.Std в этой вехе меняются
только по явному решению организатора с обоснованием в приказе этапа, а **железная
поверхность API-8 (IConsoleApi, зеркала Cartridge, Q, Fix/SMath/Button/Font) —
только через ADR (ADR-024); приказная оговорка её не заменяет**.

Форматы файлов (map.bin, flags.bin, gfx.png, .quarp8) НЕ меняются: редактор — новый
писатель существующих форматов, не новый формат. Доказательство — round-trip
байт-в-байт на арте демо. Исключение возможно только через ADR (например, «# width N»
из debt-map-csv-hand-authoring — решить на этапе карт).

# Этап 1. Скелет оболочки: три режима, библиотека игр, спайк UI

Режимы названы владельцем (гриль входа, уточнение): **библиотека игр ↔ игра ↔
редактор игр**. Прецеденты ниши — Splore (PICO-8) и SURF (TIC-80): встроенная
библиотека картриджей — норма жанра; загрузка сразу в неё — наше следствие
ADR-009 (терминала-самохоста у нас нет).

## Что здесь считается сделанным

1. У оболочки появляются режимы: Библиотека ↔ Игра (↔ Редактор — заглушка
   перехода). Запуск quarp.exe без аргументов → библиотека: список картриджей
   (папки carts/ рядом с exe и в рабочей папке, И `.quarp8`-файлы — наравне,
   оба пути запуска полноправны), стрелки + Z/Enter — запуск, Esc из игры —
   обратно в библиотеку. `quarp run <cart>` работает как раньше — прямой запуск;
   **Esc в прямом запуске = выход из процесса, как сейчас** (это цикл
   разработчика/F5, библиотека в него не вмешивается).
   **Судьба `quarp run` без пути** (сейчас — окно с радугой, Program.cs): тоже
   библиотека — у факта «консоль без картриджа» один владелец. Оконная радуга
   умирает осознанно: палитра проверяется файлом `quarp pattern <out.bmp>`
   и самой библиотекой (она рисуется на Master32).
2. Спайк UI-библиотеки для будущих редакторов: самописный минимум поверх MonoGame
   против готовой библиотеки (ImGui.NET — первый кандидат). Выход спайка — решение
   организатора с замером (число строк на кнопку/список/поле, вид на экране,
   совместимость с нашим integer-scale рендером) и скриншот владельцу.
3. Жизненный цикл — честно НОВАЯ работа, а не переиспользование (находка оракула:
   оболочка сегодня рождает сессию в конструкторе и выгружает только на выходе
   из процесса; переходов посреди работы у неё никогда не было). Требования:
   - Esc из игры в библиотеку проходит через полный Dispose сессии — **save.dat
     гарантированно записан** (сейчас он пишется только в Dispose/OnExiting);
   - аудио-очередь дренируется на переходе — в библиотеке не звучит хвост игры;
   - выгрузка через collectible ALC без утечек сборок (счётчик ALC в тесте,
     красная форма — нарочная утечка).
4. Детерминизм не тронут: якоря 8/8, 12 хэшей демо, sim/replay пути без правок.

## Решения организатора

- Библиотека рисуется в НАТИВНОМ разрешении окна (это UI хоста, не виртуальный экран) —
  но стилистически на палитре Master32 и системном шрифте: лицо консоли.
- Навигация этапа 1 — клавиатура (стрелки/Z/X/Esc); мышь появится с редакторами.
- Пустой список картриджей — не радуга: подсказка «положи картридж в carts/ или
  quarp new».
- Хэдлесс-пути (sim, replay, build, pack) библиотеку НЕ показывают никогда.
  Голый `quarp` — GUI-приложение и в headless честно висит окном: это норма,
  принимается вслух; этап 1 добавляет строку в README («в скриптах — sim/replay/
  build, не голый quarp») — этим закрывается debt-demo-polish п.6 целиком.
- Библиотека = локальные файлы. Онлайн-каталог (аналог Splore-онлайн) остаётся
  в «осознанно отложено» (ROADMAP) — ссылка на Splore/SURF выше про прецедент
  встроенного браузера, не про сеть.

# Этап 2. Редактор спрайтов

## Что здесь считается сделанным

1. Из библиотеки по X над выбранным картриджем открывается редактор ЕГО листа
   спрайтов: сетка листа (выбор спрайта), холст с зумом, рисование мышью.
2. Инструменты v1 — состав ФИНАЛЬНЫЙ, сверен с нишей (отчёт разведчика
   2026-08-19: таблица PICO-8/TIC-80/LIKO-12 по первоисточникам; пересечение
   трёх = минимум жанра, весь минимум взят):
   - карандаш (ЛКМ; ластик — не отдельный инструмент, а карандаш цветом 0,
     как во всех трёх консолях); пипетка (ПКМ на холсте — паттерн PICO-8);
   - заливка в границах редактируемого региона; очистка региона (Delete);
     флип H/V; поворот 90° (регион квадратный — всегда);
   - **регион редактирования 8×8 / 16×16 / 32×32** — «зум» ниши: размер
     области листа под курсором, не лупа (мультиклеточные объекты — то, что
     Spr(n,x,y,w,h) потом собирает); масштаб отображения — отдельно, простое
     целое умножение;
   - сетка листа 16×16 спрайтов (выбор региона), **16 свотчей — только
     видимая палитра** (ПОПРАВКА к первой записи «32»: ратифицированная
     SPEC-8 §6, загрузчик MapToPalette, Sset с маской & 0x0F и энкодер —
     четыре владельца факта согласны: в листе живут слоты 0–15; парные
     оттенки — runtime через Pal);
   - Undo/Redo (Ctrl+Z/Ctrl+Y), стек снапшотов листа в памяти сессии;
   - сохранение Ctrl+S; Esc с несохранёнными правками — строка-подтверждение
     в футере (сохранить и выйти / выйти без / остаться), не молчаливая
     потеря и не модальный диалог.
   Отложено с записью (idea-sprite-editor-v2): выделение+move, копипаст
   спрайтов, фигуры, размер кисти, pan, предпросмотр парных через Pal.
   Волны: **2b** — ядро (режим, мышь, холст, карандаш/пипетка/свотчи, undo,
   контракт сохранения); **2c** — преобразования (заливка, флипы, поворот,
   очистка, регионы) поверх ядра.
3. Сохранение: **чистая сессия не пишет на диск вовсе** (байт-в-байт бесплатно);
   грязная — пишет собственным ДЕТЕРМИНИРОВАННЫМ PNG-энкодером (фиксированные
   фильтр и настройки сжатия: одни пиксели → одни байты, всегда и везде).
   Пиксельный round-trip закреплён тестом: decode(encode(decode(f))) ==
   decode(f) для gfx.png всех демо; повторное сохранение того же листа — те же
   байты. У картриджа без gfx.png (змейка) редактор показывает пустой лист
   и создаёт файл первой грязной записью.
4. Мышь появляется в оболочке впервые — только в редакторе; библиотека остаётся
   клавиатурной.
5. Хром (кнопки, свотчи, скролл) считается против фальсификатора ~500 строк
   (раздел спайка выше) — число строк хрома в отчёте обязательно.

## Решения организатора

- PNG-энкодер живёт в CartKit рядом с нашим же декодером (симметрия; Shell
  не пишет форматы сам). Это НЕ железо API-8 — ADR не нужен, формат файла
  не меняется (PNG остаётся PNG, Aseprite остаётся рабочим путём — ADR-026).
- Редактируется файл картриджа-папки (carts/<имя>/gfx.png). .quarp8-файлы
  в v1 редактора не редактируются (read-only запись в библиотеке — честная
  надпись, не сюрприз при сохранении); распаковка .quarp8 в папку — не эта веха.
- Правка gfx.png под работающей игрой невозможна по построению (редактор
  и игра — разные режимы одного окна); CartWatcher увидит файл при следующем
  запуске как обычную внешнюю правку.
- Прямоугольники/фигуры, выделение, копипаст спрайтов — non-goals v1
  (карточка idea-sprite-editor-v2 уже заведена). Заливка была в этой строке
  до разведки ниши — состав п.2 (финальный, по данным) её ВКЛЮЧАЕТ; строка
  поправлена по находке волны 2c: приказ противоречил сам себе.

# Этап 2.5. Переделка UX по вердикту владельца (2026-08-19)

Владелец принял этап 2 по работоспособности и ОТКЛОНИЛ по удобству. Его макет —
закон этапа и **стандарт оболочки для всех редакторов вехи** (карты, звук, код
обязаны сесть в тот же каркас):

- **Верхняя строка — вкладки, только иконки, никакого текста.** Слева — иконка
  выхода из редактора. От правого угла справа налево: музыка, звуки, тайлмапы,
  спрайты, код (то есть слева направо у правого края: код, спрайты, тайлмапы,
  звуки, музыка). Несуществующие пока редакторы — неактивные иконки с подсказкой
  (оживают в своих порциях). Никаких заголовков: ни «SPRITE EDITOR», ни имени
  картриджа, ни имени спрайта сверху.
- **Нижняя строка — статус-бар:** координаты курсора; номер/имя выбранного
  спрайта; кликабельная иконка изменено/сохранено (клик = сохранить), рядом
  кнопки undo/redo.
- **Левая колонка — тулбар инструментов, только иконки** (как в фотошопе),
  сверху вниз: выделение (прямоугольник, кисточка), карандаш, заливка,
  штамповка, фигура (овал, прямоугольник). Ниже — строка-действия иконками:
  флип H, флип V, поворот, очистка (паритет с хоткеями F/V/R/Del).
- **Правее тулбара — область рисования; правее её колонка:** палитра, под ней

  сохранении — решение владельца), под ним лист спрайтов.
- **Подсказки:** наведение на любой инструмент → через 3 секунды всплывающая
  текстовая подсказка.
- **Паритет ввода — закон:** каждое действие доступно и только с клавиатуры,
  и только мышью/стилусом/пальцем.
