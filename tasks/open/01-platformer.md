# Вертикальный платформер (обязательный худший случай №1)

Подъём по башне: платформы, прыжки, следящая камера, падение вниз — угроза.
Цель — вершина; проигрыш — падение за нижний край видимой зоны или враги/шипы.
Уровень — настоящая карта `map.csv` → `quarp map build` (Р16). Спрайты — `Sset`
в `Init()`. Звук: ≥2 sfx (прыжок, смерть) + фоновая тема. Раскладка и камера —
только от `ScreenWidth`/`ScreenHeight`.

Критерии (наблюдаемым поведением):
- с `walkthrough.input` игра проходится от старта до вершины без исключений;
  хэш прохождения ≠ хэшу холостого сима той же длины (Р20);
- при падении с максимальной высоты игрок успевает увидеть платформу под собой
  до столкновения (это и есть «окно реакции» Р7 — замерить, не подгонять);
- аудио-хэш сима 600 тиков ≠ digest тишины.

В отчёт — числа Р7: терминальная скорость падения (px/тик), видимые пиксели под
игроком при центрирующей камере, окно реакции в тиках; высота прыжка в тайлах и доля
поля; понадобилась ли «посмотреть вниз» или покомнатная камера; строк поля после HUD.

Non-goals: не трогать ничего вне carts/platformer/**; физику под порог Р7 не
подгонять (Р19); общий код с другими демо не заводить (Р18); движок не править —
дыры API возвращать находками (Р15); `dotnet build/test/run` не запускать (Р17).
