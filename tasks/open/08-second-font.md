# Второй шрифт (глиф 4×6) — выбор автора картриджа через API

**РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-08-18, плейтест M4):** в API — два шрифта, мелкий
3×5 (нынешний) и крупный 4×6; какой использовать — решает автор картриджа
в своей игре. Переключение игроком отклонено разбором организатора:
Print рисует в framebuffer, хэш кадра = детерминизм, реплеи и вёрстка
сломаются. Во встроенном редакторе кода (M9, хостовый UI вне framebuffer)
шрифт/масштаб свободны — записано туда же.

Состав работы:
- 95 оригинальных глифов 4×6 (лицензия: no borrowed fonts — рисуем своё);
- поверхность API: перегрузка Print или параметр шрифта (решение организатора
  при постановке — сверить с PICO-8 custom font и TIC-80 font() как с нишей);
- метрики крупного: ячейка 5×7 → 25 колонок на 128×72, 32 на 160×90, 40 на 8w
  мелким; возвращаемое значение Print — по фактическому advance;
- API-8 §3 дописывается ДО ратификации (этап 4) — тайминг правильный;
- тесты: глифы попарно различны; негативный контроль; якоря змейки
  неподвижны (она крупным не печатает — и не начнёт до перепина).

Порядок: ПОСЛЕ перерисовки строчных 3×5 (bug-font-readability, в работе —
та же зона Core) и ДО гриля вердикта: владелец должен сравнить диалог
крупным шрифтом на 128×72 и 160×90 вживую — это доказательная база развилки
«25 колонок против 32».

Критерий (наблюдаемым поведением): диалоговая сцена печатает прозу крупным,
HUD мелким в одном кадре; оба walkthrough-трека проходят; реплей бит-в-бит;
якоря PLAYBOOK §4 на месте без перепина.

Non-goals: мелкий шрифт и его метрики не трогать; выбор шрифта игроком
не делать никогда (детерминизм); редактор M9 здесь не строить.
