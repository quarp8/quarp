# Поднятая подсказка о несохранённом переживает переход по вкладкам

Находка второго адверсариального ревью этапа 5 вехи M9 (не блокер, коммит не задерживала).

`SwitchEditorTab` нигде не опускает поднятую подсказку о несохранённом; единственные, кто её
опускает, — `RequestClose` и обработчики Z/X. Отсюда живой сценарий:

1. автор рисует на листе спрайтов, банк грязный;
2. жмёт EXIT в меню паузы — поднимается подсказка «уходить с несохранённым?»;
3. передумывает и уходит по `F1`/`F3` на другую вкладку — подсказка остаётся поднятой,
   но экран уже другой;
4. позже он жмёт обычное `Z` на этом экране — и это означает не «сохранить», а
   **«сохранить и покинуть картридж»**. При прямом запуске (`quarp run <cart>`) конец этой
   цепочки — выход из процесса.

То есть нажатие, которое автор считает безобидным, уводит его из картриджа, а в одном случае
закрывает консоль. Ни один тест этого не покрывает.

Решить: подсказка обязана опускаться при уходе с того экрана, где её подняли, — либо
переход по вкладкам её отменяет, либо она рисуется поверх любой вкладки и остаётся честной.
Выбрать одно и записать причину; молча оставить «висит и ждёт чужого Z» нельзя.

Негативный контроль: игра → рисунок на листе → `F1` → EXIT → `F1` → `F3` →
`SaveEditorAndClose()`; ждём `Mode == Editor`, сейчас получаем `Library` (или `ExitRequested`
при прямом запуске).

Non-goals: механизм самой подсказки (`RaiseDirtyBankPrompt` — единый владелец вопроса,
введён этапом 5) не переделывать; семантику Z/X не менять.
