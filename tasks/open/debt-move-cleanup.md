# Хвосты переезда, отложенные из-за CartIdentity — находки адверсария 4.0

Всё ниже — комментарии/утверждения, чья правка сдвигает CartIdentity картриджа
(и для змейки — sha256 голдена), поэтому чинится ПАЧКОЙ при следующем осознанном
пересборе, не поштучно:

1. **plan-golden.cs: off-by-one планировщика против рекордера** (запись T
   применяется рекордером на тике T+1, планировщик применяет на T; жив на одном
   тике запаса MinStepInterval=3). Предупреждение вписано в шапку файла; починка
   выравнивания = новые байты golden.input = перепин sha256. Чинить вместе со
   следующим пересбором голдена + добавить сверку «прогноз планировщика ==
   финальный хэш записи».
2. **Комментарии пяти демо ссылаются на удалённый спайк** (--profile 8w, «128x72
   and 160x90», «eight screens at 128x72»): dialogue main.cs:16, platformer :10,:31,
   shmup :203, breakout :17, digger :729-730. Правка = сдвиг CartIdentity всех пяти.
   Чинить при конверсии на библиотеку (этап 4.1) — она и так пересоберёт всё.
3. **snake main.cs:374-380**: комментарий «2 px spent on bottom border» — по факту
   1 px (y=89 — фон). README уже исправлен; комментарий — при следующем пересборе
   голдена (см. п.1, один заход).
4. **TestPatternTests**: «PatternFillsEveryPixel» не ловит незакрашенный пиксель
   (0 < 32 проходит); дыра в середине пройдёт. Добавить настоящий контроль
   (например, рендер на префилл 255 и проверка отсутствия 255) — тесты якорей
   не двигают, можно раньше остальных пунктов.

Критерий: после пачки — grep «8w|--profile|128x72» по carts/*/src пуст; прогноз
планировщика сверяется с записью автоматически; негативный контроль паттерна
