# Коллизии из коробки — третья подтверждённая боль ниши

Наблюдение владельца (2026-08-18): несколько авторов на YouTube независимо
называют ручное кодирование коллизий «геморроем PICO-8». Это рыночный сигнал
того же рода, что две боли ADR-019 (отладка, таймеры), — и он сходится с нашими
собственными повторами этапа 3 (later-stdlib-candidates):
- AABB Overlaps — руками в breakout (3 формы) и shmup;
- тайловый контроллер персонажа (бокс против карты, one-way платформы, coyote,
  буфер прыжка) — platformer, ~120 строк;
- сеточные проверки Mget/Fget-флагов — digger, platformer.

Кандидаты семейства (подтверждать повторами, не фантазией — Р10):
1. AABB: Overlaps/Contains — уже 2 наблюдения, почти порог;
2. бокс-против-карты по флагам тайлов (движение с разрешением по осям) —
   ядро жанровой боли, у PICO-8 её решает каждый автор заново;
3. tile-контроллер платформера (one-way, coyote, буфер) — верхний этаж,
   возможно M10-туториал вместо библиотеки — решить по спросу.

Куда НЕ идёт: в железный API консоли (ADR-019 — железо перманентно и крошечное;
коллизии живут в Quarp.Api-библиотеке и не съедают бюджет картриджа).

Порядок: минимальный слой (1+2) — кандидат в библиотеку этапа 4 при подтверждении
порога повторов; контроллер (3) — после релиза по реальному спросу авторов.

Критерий: автор пишет платформер, не написав ни одной строки пересечения
прямоугольников и разрешения по осям; демо-картриджи (кроме змейки — носитель
якорей) переводятся на библиотеку как её первое доказательство.

Статус после оракула 4.1 (2026-08-19): AABB подтверждён в 2 демо из 6 — ПОД
порогом Р10 (бокс-против-карты платформера — другая строка семейства, git log -S
третьего вхождения не нашёл). В Std v1 не входит; ждёт повторов после релиза
или записанного решения владельца об отклонении от Р10.

Non-goals: физический движок не строить (не наш жанр); в SPEC-8/API-8 не вносить.
