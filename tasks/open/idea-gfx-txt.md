# У листа спрайтов нет текстового конвейера

Находка бригады P (этап 3), подтверждённая счётом накопителя: у звука есть
sfx.txt → sfx.bin, у карты map.csv → map.bin, у спрайтов — только PNG (Aseprite,
для людей). Каждое демо, строящее спрайты кодом (Р16), написало свой парсер
«строка hex-символов → Sset»: shmup, digger, dialogue, platformer — четыре
независимые копии одного конвейера, просто внутри Init().

Решить на этапе 4 или позже (M9 несёт встроенный редактор спрайтов — не
дублировать его раньше времени): `gfx.txt` → лист тем же `quarp gfx build`
по образцу пары sfx; либо решение «спрайты из кода — легитимный путь»
записывается в документацию, а парсер уезжает в библиотеку (см.
later-stdlib-candidates, строка «Спрайты из текста», счёт 4).

Критерий: автор без Aseprite делает спрайты, не написав парсер сам.

Non-goals: не делать до вердикта; формат gfx.png и правило палитры не трогать.
