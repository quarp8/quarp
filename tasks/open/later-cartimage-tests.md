# Тесты формата картинки: идентичность, байт-равенство, отказы

Формат обещает две вещи, на которых стоит всё остальное
([CART-IMAGE-FORMAT.md](../../docs/CART-IMAGE-FORMAT.md) §6), и обе обязаны проверяться
отдельно, потому что ломаются независимо: первое — про упаковщик, второе — про загрузчик.

1. `payload(pack --png F)` **побайтово равен** `pack F` — на всех шести демо.
2. `identity(load(F.quarp8))` равна `identity(load(F.quarp8.png))` — все 32 байта,
   на всех шести демо. Негативный контроль: правка одного байта в `src/**/*.cs` двигает
   обе одинаково.

Дальше — красные формы, каждая обязана уметь краснеть:

- геометрия не 2240×1484 → отказ с обоими размерами;
- нет маркера `QIMG` (взять настоящий `carts/snake/gfx.png`) → отказ, не исключение;
- версия 2 в заголовке → отказ с обоими номерами (правило 1 из §7);
- испорченный байт payload'а → отказ по CRC;
- `payloadLength` больше ёмкости канвы → отказ до всякого чтения;
- пакет больше 1 246 544 байт → упаковщик отказывается **до** записи файла, как это делает
  `Quarp8Package.Pack` с бюджетом 320 КБ;
- `cover.png` отсутствует / не 160×90 / содержит не-мастер-цвет → три разных отказа
  с координатами пикселя в третьем.

Отдельно — тест на выживание, потому что именно он ловит регрессию «формат уехал в чанк
или в альфу»: картинка, пропущенная через **пересохранение PNG** и через **квантование
в 256 цветов**, грузится по-прежнему (замеры ADR-039: 100.00 % битов).

Критерий: все перечисленные проверки существуют и показаны красными на подмене; якоря
`scripts/check-anchors.sh` и двенадцать хэшей демо не двигаются ни на бит (картинки нет
ни у одного демо, идентичность не трогается).

Non-goals: sha256 самой картинки в якоря CI **не вносить** — контейнер не обещан
побитово одинаковым между версиями рантайма (ADR-039); якорь — sha256 вынутого payload'а.
